KI-Assistenten

Sie können einem KI-Assistenten (z. B. über den MCP-Server von Home Assistant) Zugriff auf die ComfoBox geben. Der Assistent liest dann dieselben Werte, die Sie in der Oberfläche sehen – und kann – wenn Sie es erlauben – Sollwerte schreiben.

Die KI ist nur ein weiterer Client. Sie benutzt dieselben Regeln wie die Web-Oberfläche: Min/Max, erlaubte Auswahlwerte und der 24-h-Schreibschutz gelten unverändert.

Zwei Wege

Weg Was die KI sieht Voraussetzung
Home-Assistant-MCP die Entitäten und Dienste der HACS-Integration HA-MCP-Server ist eingerichtet
REST-API den vollständigen Item-Katalog mit Grenzen API-Token mit passendem Umfang

Beide Wege führen zum selben Gateway. Für reine Leseaufgaben ist MCP einfacher; für präzise Schreibaufgaben mit Grenzwerten ist die REST-API geeigneter.

Über Home-Assistant-MCP

Die HACS-Integration legt ein Gerät ComfoBox ELESTA an. Der MCP-Server von Home Assistant stellt dessen Entitäten dem Assistenten zur Verfügung.

Welche Entitäten gibt es?

Werttyp Entität
Zahl, nicht schreibbar Sensor
Zahl, schreibbar Number
Auswahl, schreibbar Select
0/1-Wert, schreibbar Schalter
Verbindungszustände Binary Sensor

Wie heißen die Entitäten?

Die Entitäts-ID wird aus dem Geräte- und dem Wertnamen gebildet, zum Beispiel:

number.comfobox_elesta_raumsollwert_normal
sensor.comfobox_elesta_aussentemperatur
select.comfobox_elesta_betriebsart

Verlassen Sie sich nicht auf geratene IDs. Die exakten IDs und die erlaubten Werte stehen in Home Assistant unter Einstellungen → Geräte & Dienste → ComfoBox ELESTA. Ein Assistent sollte die IDs von dort übernehmen, nicht aus dem Namen ableiten.

Dienste

Dienst Zweck
comfobox.set_value Wert schreiben (entity_id + value)
comfobox.read_all alle Werte sofort neu lesen
comfobox.restart Gateway neu starten

Ein Schreibauftrag sieht zum Beispiel so aus:

service: comfobox.set_value
target:
  entity_id: number.comfobox_elesta_raumsollwert_normal
data:
  value: 21.5

Auswahlwerte (Select) werden mit dem exakten Namen geschrieben, z. B. Automatic – nicht mit einer Zahl und nicht übersetzt.

Über die REST-API

Die REST-API eignet sich, wenn der Assistent direkt HTTP sprechen kann. Sie liefert zu jedem Wert die Grenzen und die erlaubten Auswahlwerte mit:

Feld Bedeutung
id stabiler Schlüssel für Schreibvorgänge
value der aktuelle Wert (Zahl)
unit die Einheit
min / max der erlaubte Bereich
writable darf dieser Wert geschrieben werden?
enumValues die erlaubten Auswahlwerte
stale ist der Wert veraltet?

Ein Überblick über alle Endpunkte steht unter API.

Was Sie dem Assistenten sagen sollten

Geben Sie dem Assistenten diese Regeln mit – sie verhindern die typischen Fehler:

  1. Erst lesen, dann schreiben. Der aktuelle Wert und die Grenzen kommen aus dem Gateway (GET /api/items bzw. die Entität).
  2. Nur Werte innerhalb von min/max vorschlagen. Keine geratenen Grenzen.
  3. Auswahlwerte exakt so schreiben, wie sie in enumValues stehen.
  4. Nicht im Sekundentakt schreiben. Jeder Schreibvorgang zählt auf das 24-h-Limit (Standard 200).
  5. Experten-Werte nicht ohne ausdrückliche Freigabe schreiben.
  6. stale = true bedeutet: der Wert ist veraltet – nicht darauf regeln.

Sicherheit

Empfehlung Begründung
Nur lesen als Standard ein Lese-Token kann keinen Sollwert verändern
Eigener Token für die KI jederzeit widerrufbar, ohne andere Programme zu stören
MQTT abschalten, wenn Sie nur MCP/REST nutzen weniger offene Schnittstellen
Kein Zugriff aus dem Internet das Gateway gehört ins Heimnetz

MQTT abschalten

Wenn Sie die HACS-Integration oder die REST-API nutzen, brauchen Sie keinen MQTT-Broker. Schalten Sie MQTT ab:

  • Web-Oberfläche: Konfiguration → MQTT → MQTT aktiviert aus → Speichern → neu starten
  • HA-Add-on: Feld Broker-Host leer lassen
  • Docker / Synology: COMFOBOX_Mqtt__Enabled=false

Danach gibt es keine MQTT-Verbindung, keine veröffentlichten Topics und keine Schreibbefehle über MQTT. Die REST-API und die HA-Integration funktionieren unverändert. Details: MQTT.
